# 兩條路：A 把 Excel 搬進來，B 把程式藏進 Excel

2026/08/19 整理。**當天的結論是走 A**（規劃寫在 `介面規劃.md` 第十七節），
但 B 沒有被否掉到不能翻案 —— 這份文件把兩邊的帳都留著，
以及「什麼事情發生了就該重新討論」。

## 兩條路想解決的是同一件事

原本操作一天的交易只碰兩樣東西：網頁跟 Excel。這支程式做成「橋樑」之後變成三樣，
而且多出來的那一樣沒有取代掉任何東西。三項工具的使用頻率是不平均的：

| 工具  | 一天用幾次                                     |
| ----- | ---------------------------------------------- |
| 網頁  | 下單的時候                                     |
| Excel | **整天都在按**（更新股價 → 填比重 → 自動計算） |
| 程式  | 一次（收工同步）                               |

問題不是「多了一個工具」，是**多了一個工具，但整天在用的那個沒被吸收**。
兩條路都是把三項收回兩項，差別只在**留下哪一個當家**：

|        | **A：Excel 搬進來**              | **B：程式藏進 Excel**                          |
| ------ | -------------------------------- | ---------------------------------------------- |
| 當家的 | 程式                             | Excel                                          |
| 另一個 | Excel 降成存檔／備援             | 程式降成背後的常駐工人                         |
| 長相   | 介面上長出持股表、試算、自動計算 | Excel 上多一顆按鈕，按下去跳 MsgBox 說寫了什麼 |

## 對照

| 項目                | A：Excel 搬進來              | B：程式藏進 Excel                 |
| ------------------- | ---------------------------- | --------------------------------- |
| 真的收成兩項工具？  | 是                           | 2.5，開盤前仍要開一次介面（見下） |
| 開發量              | 大，約 +1000~1500 行         | 小，HTTP 層 + VBA 按鈕            |
| 移植風險            | 有：15 條公式 + 求解器要搬對 | 零，公式與巨集原地不動            |
| Excel 的即興自由    | **失去**                     | 完整保留                          |
| `自動計算` 弄髒格子 | 消失（變成純函式）           | 留著，而且多一個併發對手          |
| `ledger` 狀態機     | 第三段可以砍掉大部分         | 永遠留著，而且更吃重              |
| 20 帳號的維護       | 一份程式                     | 20 分頁 × 73 公式，5 檔上限跟著留 |
| 出錯時看到什麼      | Python 的錯誤訊息與 log      | VBA 的 MsgBox，或 Excel 直接卡住  |
| 成本的形狀          | 一次付清                     | 前期便宜，長尾慢慢冒              |

**最後一列是決定的關鍵。** B 前期便宜，但把整類併發與生命週期問題永久留在系統裡
（Excel 突然卡住、值被還原、格子莫名轉手動、常駐進程半夜死掉隔天才發現），
而且那些全部發生在 VBA 那一側 —— 沒有 log、沒有堆疊、只有 MsgBox。
A 的成本則誠實而且一次性：移植風險可以用「逐格對帳」壓到接近零，
開發量可估，唯一真正換不回來的是 Excel 的即興自由。

## A 這條路

細節全部在 `介面規劃.md` 第十七節。摘要：

- 要搬的東西有 10 項，73 個公式格去掉重複後只有 15 條不同的公式
- 真正有份量的只有 `自動計算` + `Sim_trade` 這支求解器（361 行 VBA 的核心）
- 分三段：**計算層 + 對帳** → **介面長出來** → **收掉橋接邏輯**
- Excel 保留成「可以獨立運作的完整檔案」，寫回時把所有輸入格寫滿，公式與巨集不碰

**成立的前提**（2026/08/19 使用者親口確認）：每天在 Excel 上的動作只有四個 ——
按「更新」抓股價 → 填 5 個預計比重 → 按「自動計算」→ 看下單試算，
換股時多一個「刪掉舊的、加進新的」。**沒有在空白格即興算東西、
沒有整欄複製貼上、沒有開多分頁對照。**

## B 這條路

架構：Excel 按鈕（VBA）→ 本機小埠 → 常駐 Python 進程（養著已登入的瀏覽器）
→ 抓資料 → 走 `ledger`／`planner` → COM 寫回 Excel → 回訊息。

搭配的三個選擇：

- 瀏覽器登入完自動最小化到工作列（不用無頭模式，憑證會出事）
- Excel 上另加一顆「收工」按鈕關掉常駐
- 按下去同步等結果，跳 MsgBox 告訴你寫了什麼

### 規劃時挖出來、真要動手不能忘的（原本就記著的五點）

**一、一個瀏覽器同時只帶得動一個帳號的身分。** 同一個 context 共用 `JSESSIONID`，
後登入的頂掉前面的。但這只是瀏覽器這一邊的事：伺服器上 20 個帳號是 20 個
各自獨立的 session，B 登入不會殺掉 A 的。2026-08-19 已經照這個做法改掉了 ——
登入時把每一組的 cookie 收起來，換人就換 cookie（見 `fetch.new_store`），
不必重登；只有那一組在伺服器上逾時了才會真的重登一次。常駐服務沿用同一份 store 就好。

**二、VBA 必須用非同步 XMLHTTP + `DoEvents` 迴圈，不能用同步 `send`。**
同步會把 Excel 的訊息幫浦鎖死，而常駐進程正要用 COM 回頭寫這個 Excel
→ 直接卡成「Excel 正在等待另一個應用程式完成 OLE 動作」。

**三、寫入一定要存檔，即使是接上你開著的 Excel。** 不存的話紀錄檔記成「寫過了」、
檔案卻是舊的，帳本跟檔案分家而畫面上沒有任何徵兆。`ui.py` 已經為這件事改過一次
並留了理由（現在在 `ui.py:1541-1547`，`todo.txt` 裡記的 `1032-1039` 行號已經漂了）。
（`update_excel.py` 這支 CLI 2026/08/20 已經整支拿掉，這條「不要跟 CLI 走」的
提醒本身已經沒有 CLI 可以跟了，但道理不變：常駐服務動手寫入前一定要存檔。）

**四、常駐模式只能走例行那條路。** 這一點寫的時候還有「接管（`--adopt`）」跟
`B8` 需要人判斷「含不含今天的淨收付」這套機制；2026/08/20 整套自動/手動偵測、
`--adopt` 都拿掉了（見 [[remove-manual-detection]]），現在股數/成本/現金一律
覆蓋，沒有「接管」這個概念。但「開盤前開一次介面確認狀態、之後整個交易時段
在 Excel 按按鈕」這個流程判斷本身不受影響，因為它談的是操作節奏，不是接管
機制。

**五、分頁名稱對不到帳號。** `.env` 只有帳密沒有名字，帳戶名要登入後才從
sessionStorage 拿得到。所以常駐第一次要整批登入建對照表，
之後才能「按哪個分頁就更新哪個交易人」。

### 2026/08/19 查巨集之後補上的四點

前兩點是讀了 Excel 裡那 361 行 VBA 才發現的，也是這次沒選 B 的主要理由。

**六、`自動計算` 巨集會反覆寫壞程式負責的那三塊格子，而且整支沒有錯誤處理。**
它的做法是把 Excel 的格子當變數用 —— 迭代過程中反覆把試算股數寫進 `E4:E8`、
重算成本寫進 `F4:F8`、現金寫進 `B8`，讓 Excel 重算公式，
再讀 `F14:F18` 的比重回來看收斂了沒，收斂之後才復原。
而 361 行 VBA 裡**一個 `On Error` 都沒有**（`自動計算` 尾巴那個 `over:`
是沒人跳的死標籤）。迭代中途炸一次，復原那段就不會跑，
Excel 上會留著看起來完全正常的模擬值 —— 下次同步一比對，`last_written` 對不上，
那幾格判定成「人手改過」轉手動、從此不再更新，而且畫面上不會說是為什麼。

走 B 的話這支東西繼續活著，跟常駐進程共用同三塊格子。走 A 它變成純函式，問題消失。

**七、「人正在編輯儲存格」會擋掉 COM 寫入，而 VBA 沒有 `finally`。**
第二點的非同步 + `DoEvents` 解掉的只是「同步 `send` 鎖死訊息幫浦」那一半；
`DoEvents` 讓 Excel 恢復回應的同時，也讓人能繼續打字。
游標停在儲存格編輯模式裡的時候，外面的 COM 寫入會被拒。
標準解法是等待期間 `Application.Interactive = False` 把鍵盤擋掉，
但 VBA 沒有 `try/finally` —— 只要那段中途出錯而沒還原，
**Excel 會變成打不了字，只能強制關掉**（還沒存的東西一起沒）。
要靠 `On Error GoTo` 手動補上所有出口。

**八、本機小埠沒有身分驗證，等於開了一個「誰都能叫它操作券商帳號」的介面。**
常駐進程握著已登入的瀏覽器與憑證。埠開著的期間，本機**任何**程式
（含瀏覽器裡的網頁）都打得到它。至少要：綁 `127.0.0.1`、
每次啟動產生一組隨機 token 寫在檔案裡、VBA 讀那個檔把 token 帶在標頭。
這支東西碰的是真錢，這一項不能省。

**九、第四點其實已經承認工具數不是 2，是 2.5。** 每天開頭仍然要開介面確認狀態。
所以 B 是「大部分時候兩項、每天開頭三項」。

## 什麼情況該把 B 拿出來重新討論

這次選 A 是掛在幾個當下為真的前提上。任何一條翻掉，就值得重新算一次：

| 前提                                    | 翻掉的話                                                  |
| --------------------------------------- | --------------------------------------------------------- |
| 每天只做那四個動作，不在 Excel 上即興算 | 開始需要即興運算 → A 會讓人每天不爽一次，B 的帳變得划算   |
| 5 檔上限夠用                            | 要放寬 → 兩條路都得重做 Excel 版面，A 的相對優勢反而變大  |
| 介面做得出可用的可編輯表格              | 第二段做完發現手感差太多 → 退回 B，第一段的計算層不會白做 |
| 願意付一次性的移植成本                  | 時間被壓縮 → B 可以先上，但要先解掉第六、七、八點         |

**第一段（計算層 + 對帳）不論最後走哪條路都值得先做嗎？**
不是 —— 走 B 的話計算留在 Excel，那一段就白做了。
所以第一段開始之前，A 這個方向要是確定的；反過來說，
第一段做完之後就會知道那 15 條公式與求解器到底有多難搬，
那時候要反悔還來得及，成本只是那一段。

## 附帶查到、兩條路都要處理的事

**一、交割款公式的賣出分支，門檻是 20 元、補收的卻是 1 元。**
買進那段是「手續費不足 1 元就收 1 元」，前後一致；賣出那段判斷
「手續費大於 20 元才照算」，不足時卻是 `-1`。而 `Sim_trade` 裡的最低手續費
處理用的又是 20 元。三處對不起來，要確認哪一個才是想要的。

**二、模擬檔的 `B5` 手續費率是空的。** 空值在 Excel 裡當 0，
所有手續費計算因此全部歸零，`自動計算` 的「手續費不足 20 元」也永遠成立。
真檔是不是也空的要確認 —— 如果是，那現在算出來的下單試算本來就沒算手續費。

這兩件事跟走哪條路無關，是 Excel 本身的問題，早晚要問清楚。
