# 全文件交叉核對 prompt 範本

用途：docs/*.md 跟程式碼註解常常各自把同一條規則講一次，改規則的時候很容易
漏改其中一處，留下矛盾的舊講法（案例見下方「已知案例」）。要做一次全面核對時，
把下面這段整段貼給 subagent（建議用 general-purpose，不要用 Explore——
Explore 的說明裡明講不適合做 design-doc auditing / cross-file consistency
check；工具只給讀取類，不給 Edit，修正的措辭要人來定）。

---

## 貼給 agent 的 prompt

這是 auto-login 專案（持股同步工具）。docs/\*.md 跟 CLAUDE.md 記錄了很多
「已經定案、已經拿掉」的功能與規則決定，因為這個專案改版很多次，舊功能不斷
被拿掉、新規則不斷取代舊規則。同一件事常常在多個檔案裡各自講一次
（CLAUDE.md、docs/\*.md、各支 .py 的 docstring / 行內註解），舊講法很容易
漏改，造成文件之間、或文件跟程式碼之間互相矛盾。你的任務是**找出這些矛盾，
不要動手修改，只列清單回報**。

**Ground truth**：先讀 CLAUDE.md，特別是「改動前必看」那幾條——這是目前最新、
最權威的規則，任何地方跟它衝突，就是那個地方錯，不是 CLAUDE.md 錯。

**步驟**：
1. 逐一讀 docs/ 底下每一份 .md，把每一段講的具體行為（公式、if/else 分支、
   某個旗標的效果、某功能還在不在）整理成清單。
2. 針對每一條具體行為，去讀文件裡點名的 .py 檔案（例如「見 ui_background.py」
   「見 planner.py」），確認程式碼現在真的是這樣運作，不是文件講的舊版本。
3. 同一件事如果在兩份以上的文件／程式碼註解裡各講一次，互相比對內容是否
   一致。

**判斷標準（重要，避免假警報）**：
- 算矛盾：某處把已經拿掉的功能／分支講成還存在；或兩處對同一件事的具體規則
  （公式、參數、if/else 分支）講的內容不一樣。
- 不算矛盾：同一件事只是換句話說、詳略不同，但事實一致（例如「20 個帳號」
  vs「多人」，這是專案裡刻意保留的用詞差異，不要回報）。
- 不算矛盾：關鍵字重複但其實是不同機制（例如「備份」在憑證遷移、歷程清除、
  Excel 寫入是三個獨立子系統，各自的備份行為不用互相比對）。

**輸出格式**：每一條矛盾用這個格式——
- 檔案:行號（衝突的兩邊都要標出來）
- 引用原文（兩邊都要）
- 為什麼是矛盾，不是單純措辭差異
- 信心程度（高／中／低）

不要修改任何檔案，只回報清單。範圍鎖定在 docs/\*.md 跟它們點名提到的 .py
檔案，不用整個 repo 每一支都讀。

## 已知案例（2026/08/25 這次人工核對抓到的，可以當校準範例）

**真矛盾（該回報）**：
- `docs/介面規劃.md`「修改今日初始現金餘額」那段原本寫「按下去之後跟著
  『程式自動更新』開關走，勾著才寫進 Excel、沒勾只顯示建議值」——但這個開關
  依 CLAUDE.md 與 ui.py 早就整個拿掉了，現在一律直接寫入。文件在講一個已經
  不存在的分支，不是措辭差異。（已修正）
- `docs/現金餘額兩種算法.md` 小節標題「還沒交割的那幾天」——內文已經改成
  明講公式「銀行餘額 + 淨收付(T+0) + 淨收付(T+1)」，標題卻還留著這次要拿掉
  的模糊講法，標題跟內文對不上。（已修正）

**不算矛盾（不該回報，當年誤判過）**：
- 「20 個帳號」與「多人 / 交易人」同時存在多處——使用者確認過這是刻意保留
  的講法差異，不是需要統一的矛盾。
- `branchId` 要不要加 `'1'` 前綴、`queryBankBalance` 金額除以 100——這幾條在
  CLAUDE.md、fetch.py、planner.py、recon.py、docs/現金餘額兩種算法.md 裡講法
  一致，不是矛盾。
- 「備份」字眼在 ledger.py（歷程清除前備份）、ui_cert.py / migrate-cert.ps1
  （憑證遷移前備份目標）、CLAUDE.md（Excel 寫入不再自動備份）三處並存——
  是三個不相干的子系統，各自獨立，不用互相比對。
