# tbbstock 自動登入 — 詳細說明

自動開啟瀏覽器、依 `.env` 裡的每組帳號各開一個分頁、自動填入身分證／密碼／驗證碼並送出登入。

**這台電腦必須有數位憑證。** 登入送出後，網站會用台網 WebCA 在瀏覽器本機檢查憑證，
沒有的話會跳出橘色的「瀏覽器查無有效數位憑證」並把你剛登入的 session 登出。
憑證存在**特定的瀏覽器 profile** 裡，不是存在 Windows、也跟 Google 帳號無關。

---

## 前提

- Windows，且已安裝 **Google Chrome**（`.env` 的 `BROWSER_CHANNEL=chrome`）
- 這台電腦的某個 Chrome profile 裡**已經有 tbbstock 的憑證**（否則見〈附錄 B〉）
- 不需要安裝 Python，不需要下載 Chromium

## 資料夾裡有什麼

| 檔案                | 用途                           |
| ------------------- | ------------------------------ |
| `tbb-login.exe`     | 自動登入主程式                 |
| `.env`              | 帳號密碼與設定（**要自己填**） |
| `setup-profile.ps1` | 手動開啟自動登入用的瀏覽器     |
| `migrate-cert.ps1`  | 把憑證複製到自動登入用的瀏覽器 |
| `chrome-profile\`   | 自動登入專用的瀏覽器資料夾     |

`chrome-profile\` 要執行過 `setup-profile.ps1` 才會出現，其餘四個檔案要**放在同一層資料夾**。
整包搬到哪都能用（同一台電腦內）。

---

## 怎麼開啟 PowerShell

`.ps1` 是腳本，**不要用滑鼠右鍵執行** —— 沒辦法帶參數，而且跑完視窗會馬上關掉，看不到結果。

1. 檔案總管進到這個資料夾
2. 空白處按右鍵 → **「在終端機中開啟」**

找不到那個選項的話：點檔案總管上方的**網址列**，把路徑刪掉、輸入 `powershell`，按 Enter。

指令前面的 `.\` 不能省略。不需要系統管理員權限。

## 首次設定（每台電腦做一次）

### 步驟 0：填 `.env`

用記事本打開 `.env`，把帳號密碼改成真的：

```
TBB_ID_1=A123456789
TBB_PASSWORD_1=你的密碼
```

多組帳號就依序 `TBB_ID_2` / `TBB_PASSWORD_2`⋯，程式會每組各開一個分頁。
沒有第二組就把 `_2` 那兩行刪掉或註解掉。

`USER_DATA_DIR=chrome-profile` **保持原樣不要改** —— 它是相對於 `.env` 所在的資料夾。

### 步驟 1：建立自動登入專用的 profile

```powershell
.\setup-profile.ps1
```

會開一個 Chrome 視窗 —— **直接關掉，不用登入任何帳號**。
這一步只是要讓 Chrome 把 `chrome-profile` 資料夾初始化出來，好讓下一步有地方放憑證。

關掉視窗後腳本會印出資料夾路徑，以及黃色的「裡面還沒有 tbbstock 的數位憑證」—— 首次設定本來就還沒有，
繼續往下做就對了。

### 步驟 2：找出憑證在哪個 profile

```powershell
.\migrate-cert.ps1
```

只掃描、不動任何檔案。輸出會列出這台電腦所有 Chrome／Edge 的 profile：

```
目標 profile: ...\chrome-profile\Default          ← 憑證要複製「進去」的地方
  目標目前沒有憑證痕跡

掃描來源 profile：
  [有憑證] Chrome / Default  (TWCACertIdxRef)   ← 找這一行
            C:\Users\你\AppData\Local\Google\Chrome\User Data\Default
  [  --  ] Chrome / Profile 1
```

記下 `[有憑證]` 下面那一行的路徑。

**如果全部都是 `[  --  ]`** → 先停下來，跳到〈附錄 B〉。

### 步驟 3：關掉所有 Chrome

包含背景程序 —— 用工作管理員確認沒有 `chrome.exe` 殘留。
瀏覽器沒關的話，資料庫裡還有沒寫入磁碟的東西，複製會拿到不完整的憑證。

### 步驟 4：複製憑證

```powershell
.\migrate-cert.ps1 -From "步驟2記下的路徑"
```

例如：

```powershell
.\migrate-cert.ps1 -From "C:\Users\你\AppData\Local\Google\Chrome\User Data\Default"
```

腳本會先備份目標現有的資料、複製、再重新掃描驗證，成功會印綠色的「完成」。

**這只是複製檔案，不會向憑證中心重新申請，所以你日常 Chrome 那張憑證不會失效**，兩邊都能繼續用。

### 步驟 5：驗證

```powershell
.\tbb-login.exe
```

沒有跳出橘色的「瀏覽器查無有效數位憑證」就成功了。

## 日常使用

- **自動登入**：直接雙擊 `tbb-login.exe`
- **登入後就直接在那個瀏覽器裡操作** —— 看盤、下單都可以，`tbb-login.exe` 的黑色視窗**放著不要關**
- **結束**：在黑色視窗按 Enter，或直接把瀏覽器視窗關掉，兩種都可以
- **手動下單**：也可以執行 `.\setup-profile.ps1`（不加參數），它開的就是同一個 `chrome-profile`，憑證在裡面，照樣能下單
- 你**日常那個 Chrome 完全不受影響**，可以照常開

「簡易看盤下單」「即時看盤下單」這類選單是用 `window.open` 另外開一個視窗，
自動登入開的瀏覽器一樣支援。要注意這兩個選單**共用同一個視窗**，
先開了其中一個再點另一個，會覆蓋掉原本那個而不是各開一個。

同一個 `chrome-profile` 一次只能被一個 Chrome 開著，所以 `tbb-login.exe` 在跑的時候不要同時用 `setup-profile.ps1` 開它。

---

## 兩個禁忌

1. **不要在 `chrome-profile` 裡按「憑證申請」**
   那是向憑證中心**重新簽發一張新的**，你日常 Chrome 那張會被取代而失效。
   要的是「複製」（步驟 4），不是「申請」。

2. **不要把 `chrome-profile` 複製到第三台電腦**
   Chrome 的加密機制和台網的裝置綁定都會讓它失效，每台電腦都要各自做一次首次設定。

## `chrome-profile` 壞掉時怎麼重做

症狀是這個資料夾本身壞了：Chrome 開不起來、`tbb-login.exe` 一直卡在開啟瀏覽器那一步、
或是複製到一半被中斷／被防毒軟體處理過。

處理方式就是**把資料夾整個刪掉重做一次**，沒有別的指令要記：

1. 先跑 `.\migrate-cert.ps1`（只掃描、不動檔案），確認來源那行還是 `[有憑證]`。
   那是重做之後唯一能把憑證複製回來的地方，掃不到就先不要往下做。
2. 關掉所有 Chrome（含背景程序），否則資料夾會刪不乾淨、留下半殘的檔案
3. 在檔案總管裡把 `chrome-profile` 資料夾**刪掉**（丟資源回收筒就好，萬一想反悔還救得回來）
4. 從〈步驟 1〉重做一次到〈步驟 5〉

注意單純想手動開瀏覽器下單、或憑證彈窗跳出來，都**不必**刪資料夾。
不加參數的 `.\setup-profile.ps1` 只會開既有的資料夾，不會刪任何東西。

## 疑難排解

| 訊息／症狀                         | 處理                                       |
| ---------------------------------- | ------------------------------------------ |
| 「因為在此系統上停用指令碼執行」   | 見下方註 1                                 |
| 跳出橘色「瀏覽器查無有效數位憑證」 | 憑證沒進到 `chrome-profile`，重跑步驟 2～4 |
| 「chrome.exe 還在執行」            | 關掉所有 Chrome 視窗與背景程序，見下方註 2 |
| 「目標資料夾正被 Chrome 使用中」   | 關掉開著 `chrome-profile` 的那個視窗       |
| 「開啟瀏覽器失敗，使用者資料夾…」  | 同上                                       |
| 「找不到帳號設定」                 | `.env` 沒跟 exe 同層，或內容還是範例值     |
| 「找不到登入欄位…」                | 網站改版了，要更新 `login.py` 裡的選擇器   |
| 腳本語法錯誤、中文變亂碼           | `.ps1` 必須存成 **UTF-8 with BOM**         |
| 掃描結果全是 `[  --  ]`            | 見〈附錄 B〉                               |

註 1：改用 `powershell -ExecutionPolicy Bypass -File .\腳本名.ps1`，要帶參數就接在後面。
註 2：確認只是背景常駐、沒在使用的話，可以在指令後面加 `-Force` 跳過檢查。

## 附錄 A：為什麼要一個獨立的 `chrome-profile`

兩個原因，都沒得繞：

1. Chrome 136 之後**禁止自動化工具連上預設使用者資料夾**（`%LOCALAPPDATA%\Google\Chrome\User Data`），硬連會一直逾時
2. 同一個 profile 資料夾**不能同時被兩個 Chrome 開著**，否則自動化在跑的時候你就不能用自己的瀏覽器

所以自動登入必須有自己的 profile，也因此憑證要複製一份進去。

## 附錄 B：如果這台電腦根本沒有憑證

`migrate-cert.ps1` 掃描結果全是 `[  --  ]` 時，有三種可能：

1. **這台真的沒申請過憑證**（最常見）
2. 憑證在**別的 Windows 使用者帳戶**下，或用的是 Firefox 這類非 Chromium 瀏覽器
3. 憑證藏在壓縮過的資料庫檔裡沒被搜到

先確認第 3 種：日常 Chrome 開 tbbstock → 按 `F12` → 上方 `Application` 分頁 →
左側 `Local Storage` → `https://www.tbbstock.com.tw` → 看有沒有 `TWCACertIdxRef` 這個項目。
有的話那個 profile 就是來源，回到步驟 4。

確定沒有的話，就直接申請一張給自動登入用：

```powershell
.\setup-profile.ps1
```

在開起來的視窗裡登入 tbbstock → 點「憑證申請」→ 完成後會顯示「憑證安裝成功，請重新登入」→ 關掉視窗。
之後 `tbb-login.exe` 就過得了。

⚠️ 如果你在**別的瀏覽器**已經有一張有效憑證，這樣做會把那張取代掉。
那種情況請改用複製的方式（步驟 2～4），不要重新申請。

## 附錄 C：多組帳號與憑證

`.env` 可以設多組帳號，但**每個身分證各自需要自己的憑證**。
同一個 profile 可以同時放多張憑證，所以只要那些憑證原本就在你複製的來源 profile 裡，就會一起過去。
如果第二組帳號的憑證在別的地方，那組還是會被憑證彈窗擋下來。
