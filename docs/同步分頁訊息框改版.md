# 同步分頁改版：拿掉現金／股票兩張表，併進訊息框

2026/08/22 定案並實作完成。現金／股票兩張表拿掉，內容併進訊息框；現金算法、
今日初始現金餘額因為是「今天的固定基準」不是「這一輪的結果」，改成常駐顯示在
右上角狀態列，不進訊息框的捲動文字。


## 版面結構

| 區塊                   | 內容                                                                 | 位置                     |

**資料來源**：訊息框內容＝歷程檔（`ledger.py` 的 `-同步歷程.jsonl`），用
`ui_common.within()` 篩「`sheet == 目前交易人` 且 `at` 是今天」，不自己另外維護
一份暫存狀態。換人只是換篩選條件，跟「歷程」分頁看到的是同一份真相；
`self.history_rows` 每次 commit 完（`ui_background.py` 的 `refresh_history()`）
已整份讀進記憶體，換人重畫只是記憶體裡篩一次。股票只列「這一輪真的有寫入」的
檔，沒異動的完全不提（風險由 warnings／左邊名單的旗標補，沒有另外印「讀到 N

**視覺上色**：原本表格用列的底色/前景色，改成 `tk.Text` 的 tag 上色，機制換了
但信號留著（負的紅字）。


## 訊息框格式規格

### 行文範例

```
19:54:23 [餘額更新] 初始餘額累加 = 893 - 238 = 655
19:54:23 [餘額更新] 銀行餘額推算 = 893 - 238 + 0 = 655
19:54:20 [股票更新] 2059 川湖　股數 2,000　成本 10.8
16:16:41 [今日初始餘額] 893
09:00:00 [警告] 第 5 列「0050 元大台灣50」在網頁庫存中已不存在
20:35:08 [異常] 登入失敗
```

- 不留「舊→新」：這是一份往下疊的今日歷程，想知道以前多少看上面／更早那行。
- 現金一律印完整算式，格式是「{算法名稱} = {算式} = {結果}」：
  - 初始餘額累加：`今日初始現金餘額 + 今日淨收付` → `893 - 238 = 655`
  - 銀行餘額推算：`銀行餘額 + 淨收付(T+0) + 淨收付(T+1) …` → `893 - 238 + 0 = 655`

  數字段落沿用既有 `item["note"]`（`planner._bank_note`／`_formula_note` 算好
  的），去掉前面的標籤文字，換算法名稱打頭。
- `[今日初始餘額]` 是獨立標籤，不套「算式 = 結果」的形狀，直接印當時數字。對應
  `by == "adopt"` 的兩種情況（今天第一次登入收 B8 當基準、或改今日初始現金餘額
  剛好沒格子要寫）——這兩種 Excel 根本沒被寫過，不是套公式算出來的異動。
  `by == "program"`（真的寫了格子）才進 `[餘額更新]`。
- 股票只列這一輪真的有寫入的欄位：股數／成本同一輪都改了列在同一行，只改一個
  就只印那一個。

### 排序、合併

- 同一輪內：現金排最前，股票照 Excel 列順序（不是歷程檔原始寫入順序——
  `planner.plan()` 是股票先、現金最後才 append，訊息框畫的時候要自己重排）。
- 整體：新的在最上面，跟「歷程」分頁同慣例（`ui_history._fill_history` 的
  `reversed(shown)`）。
- 警告／異常混進同一個時間序，同一個 `at` 內排序：異常 > 警告 > 現金 > 股票
  （`ui_sync._format_today_events`）。
- 股數／成本合併規則：同一檔股票名稱（從 `label` 拆出，例如「股數（2059 川
  湖）」取「2059 川湖」）＋同一個 `at` 時間戳全等——同一輪寫入的兩筆事件
  `at` 會完全一樣。

### 紅字

只看「現在是不是負的」（`new < 0`），不看「是不是這一輪才變負的」——跟名單
上現金負的名字變紅同一規則，`[今日初始餘額]` 也適用。算式本身不管正負都照
印，只有整行顏色是例外：

```
19:54:23 [餘額更新] 銀行餘額推算 = -893 + 238 + 0 = -655      ← 整行標紅
```

### 現金 dedupe：只影響訊息框顯示

`ui_sync._dedupe_cash_rows`：現金事件按時間比對，結果（`new`）跟上一筆顯示過
的一樣就整筆丟掉；只有「今天第一筆」或「數字真的變了」（含正負轉換）才留下
顯示。**不動 Excel 寫入或歷程檔**——B8 照樣每次覆蓋、「歷程」分頁一筆不漏，
只有訊息框看不到連續重複的那幾筆。

副作用：訊息框可能連續多輪沒有新行。所以常駐狀態列固定顯示「現金餘額」現在
算出來的數字（`ui_sync._fill_status`），不管訊息框有沒有印新行——訊息框回答
「發生了什麼事」，狀態列回答「現在是多少」，兩件事分開。

### `quiet_label`（✓ 與網頁一致）

常駐狀態列項目，讀成功（或改完今日初始現金餘額）之後原地顯示：

```
✓ 與網頁一致（19:16:42）
```

- 時間來自 `self.round_at[name]`。
- 被擋住（現金還沒設基準）或有提醒在跑的時候不顯示。
- 每次讀取／修改今日初始現金餘額都是**原地覆蓋，不是疊加**——跟訊息框「按
  幾次疊幾行」的時間序刻意不同，因為這句話多數輪次都成立，疊起來反而是雜訊。
- 顏色用 `self.colors.success`（綠）。
- 文字統一「與網頁一致」，不逐項細講股票／現金各自狀態。

### 標題掛名字

`ui_layout.LabelFrame` 標題動態掛「{交易人}　訊息」，貼框邊、不隨內容捲動，
換人立刻看得到（`ui_sync._fill_right`）。字級從 `HINT_SIZE` 加大兩級——兩張
表拿掉之後這裡是唯一逐行讀的內容。

### 提醒／異常併入時間序

- **股票警告**（`_warning_line`）：文字縮短，拿掉說明性尾巴。「同一檔股票在
  網頁上佔好幾列，已用股數加權平均合併成本」這則提醒整個拿掉——目前的交易
  方式（同一天分批用現股買賣）不會觸發多列情境；合併計算邏輯本身還留著防真
  的資料不對時算錯持股，只是拿掉那句用不到的提醒（`merge_holdings()` 回傳值
  從 `(merged, notes)` 簡化成只回 `merged`）。時間戳來自 `self.round_at[name]`
  （`self.warnings[name]` 本身不帶時間）。現金被擋住的提示（`planner._cash`
  append 的 `[現金] ...`）還在討論中，暫維持排在最後，不進這個時間序。
- **整組帳號失敗**（`_error_line`）：按交易人分流，`self.problem_of[order]`
  是 `{"text":..., "at":...}`；`ui_sync._fill_notes` 用 `self.trader_of.get
  (order)` 反查對應交易人，只把屬於自己那幾組的失敗原因併進自己的訊息框。文
  字不帶「第 N 組：」前綴（人是誰已經在框標題上了）。極少數查不出交易人的情
  況（`trader_of` 也沒有這個 order）退回舊做法：不管選中誰都顯示，前綴補回
  「第 N 組：」。不套「今天」篩選——這是持續到「這一組自己再讀一次成功為
  止」的狀態，不是一次性事件，舊的一樣顯示，只是時間較舊會排到後面。


## 常駐顯示區（不進訊息框）

現金算法、今日初始現金餘額、「修改今日初始現金餘額」按鈕、`quiet_label`，都
在右上角這一排，不管這一輪有沒有異動都在。現金算法維持可點切換（`.env` 的
`CASH_METHOD_TOGGLE` 照舊管得到要不要開放點擊）。


## 注意事項（容易改壞的地方）

- **紅字判斷是 `new < 0`，不是「這一輪轉負」**（`old >= 0 and new < 0`）：後
  者在連續負值時只有轉負那一筆有紅字，後面幾筆「早就負的」反而沒有，看起來
  像沒事——已踩過一次坑才改掉，別改回去。
- **`quiet_label`／常駐狀態列是原地覆蓋，訊息框的行是疊加**：兩種資料本質不
  同（「現在的狀態」vs「這一輪發生的事」），別混用同一種更新方式。
- **現金 dedupe 只動訊息框顯示，不動 Excel 寫入或歷程檔**：B8 照樣每次覆蓋，
  「歷程」分頁照樣一筆不漏。
- **同一輪內訊息框排序是自己重排**（現金前、股票照 Excel 順序），不是照歷程
  檔原始寫入順序（歷程檔裡股票在前，因為 `planner.plan()` 股票先 append）。
- **`[今日初始餘額]` 跟 `[餘額更新]` 是兩種不同語意**：前者 Excel 根本沒被寫
  過（`by == "adopt"`），後者才是真的套公式寫了格子（`by == "program"`）。別
  為了統一格式把兩者合併，會讀起來像「有什麼被更新了」卻看不到任何數字。
- **股數／成本合併靠「股票名稱＋同一個 `at`」全等判斷**，不是靠 index 或寫入
  順序。
- **「當日淨收付」沒有整個改名成「今日淨收付」**：那是 `fetch.py` 裡實際的查
  詢資料欄位名（`record["當日淨收付"]`），`planner.py`／`recon.py`／
  `dev_tools/simulate.py` 都照這個字串存取資料，動了資料就抓不到。只有
  `ui_common.ask_cash_method` 裡當一般說明文字用的那處改成了「今日淨收付」。
