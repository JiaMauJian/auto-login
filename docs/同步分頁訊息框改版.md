# 同步分頁改版：拿掉現金／股票兩張表，併進訊息框

2026/08/22 討論定案，還沒動手實作。這份文件是給下一次對話接手用的完整規格，
獨立讀也看得懂，不必回頭翻對話記錄。


## 動機

使用者原本的問題：「我真的需要現金表格和股票表格嗎？我需要的只是網頁抓到了
什麼、它又把 Excel 變更了什麼，顯示在訊息框就好，對吧？」

現況（`ui_sync.py`、`ui_layout.py`）：右半邊是兩張 Treeview 並排——左邊
`self.cash_tree`（現金餘額／今日初始現金餘額／現金算法三列），右邊 `self.tree`
（一檔股票一列，股數／成本兩欄），底下才是 `self.warn_box` 訊息框放提醒與
現金算式說明。這兩張表大半列平常都是「跟網頁一致，沒事」，真正要看的一兩格
被淹沒在裡面；而且訊息框裡本來就已經在講「這個數字怎麼來的」，跟表格內容
有重複。

結論：兩張表整個拿掉，內容併進訊息框；現金算法、今日初始現金餘額因為是
「今天的固定基準／設定」而不是「這一輪的結果」，改成常駐顯示在別處，不進
訊息框的捲動文字。

風險是「沒辦法一眼確認今天真的抓到全部檔的網頁資料」——這個由 warnings
（例如「網頁庫存已無此檔」）跟左邊名單的整體狀態旗標補，不在這次改版的
訊息框裡另外加一行「讀到 N 檔」之類的小結（討論過，最後沒有採用這個提案，
維持單純）。


## 資料來源：直接借用歷程檔，不要自己另外管狀態

關鍵決定：訊息框不要自己維護一份「這一輪的暫存結果」再自己想辦法保留、清除。
專案裡已經有現成的東西完全符合需求——**歷程檔**（`ledger.py` 裡的
`-同步歷程.jsonl`，`planner.commit()` 每次真的寫入 Excel 就會 append 一筆
事件：`at`／`sheet`／`cell`／`label`／`by`／`old`／`new`／`note`，「歷程」
分頁 `ui_history.py` 就是拿這份檔案篩選著看的）。

做法：訊息框內容 = 這份歷程資料，篩選成「`sheet == 目前選中的交易人`
且 `at` 是今天」（沿用 `ui_history.within()` 那套邏輯），重新排版成一行一句話。

好處：
- 不用自己想一套「換人／重開程式資料要不要保留」的狀態機——資料本來就在磁碟上，
  按 `sheet` 分好了，換人只是換篩選條件
- 跟「歷程」分頁看到的是同一份真相，不會兩邊對不起來
- `self.history_rows` 已經在 `refresh_history()`（每次 commit 完都會呼叫，
  見 `ui_background.py`）裡整份讀進記憶體了，換人重畫訊息框只是在記憶體裡
  篩一次，不必碰硬碟

**沒被寫入、因此不在歷程裡的東西**：現金被擋住不寫的那幾句提示（例如「B8 是
空的，請先填一個現金餘額」）、股票「網頁庫存已無此檔」的提醒。這些維持現在
的 `warnings` 機制，排在今日歷程清單之後，跟「今天已經發生過的事」分開。


## 訊息框最終格式規格

### 標籤與行文

```
19:54:23 [餘額更新] 655
19:54:20 [股票更新] 2059 川湖　股數 2,000　成本 10.8
```

- 標籤統一叫「更新」：`[餘額更新]`、`[股票更新]`（不是「異動」）
- **都不留「舊 → 新」**：這是一份會往下疊的今日歷程，想知道以前是多少，看
  上面／更早的那一行就有了，不必在同一行重複兩個數字
- 股票只列這一輪真的有寫入的欄位：股數／成本同一輪都改了就兩個一起列在
  同一行；只改了一個，那行就只寫那一個（合併規則見下面）
- 現金公式（`銀行餘額 + 淨收付(T+0) + 淨收付(T+1)` 那種展開式）**不放在這裡**，
  那已經在切換現金算法的對話框裡講過一次了（2026/08/22 已經改完，見
  `ui_common.ask_cash_method`），平常這裡只顯示算出來的那個數字

### 現金轉負，唯一的例外

平常現金更新就是一行一個數字（如上）。**只有這一輪把餘額從正轉負的那一次**，
例外印出完整算式，整行標紅：

```
19:54:23 [餘額更新] 銀行餘額推算 = 銀行餘額 + 淨收付(T+0) + 淨收付(T+1) = -893 + 238 + 0 = -655
```

這句就是既有的 `item["note"]`（`planner._bank_note`／`_formula_note` 算好的，
兩種算法都有各自版本，不是只有銀行餘額推算才有這個待遇）。平常不顯示，只在
「轉負」這個少見、值得多看一眼的時刻例外印出來——沿用原本 `ui_sync._cash_turned`
「餘額轉負」特別提示的精神，只是從「排在說明最前面」改成「整行標紅、印出完整
算式」。

### 排列規則

- **同一輪內**：現金固定排最前面，股票照 Excel 列的順序排在後面——不管歷程檔裡
  實際寫入的先後（`planner.plan()` 是股票先、現金最後才 append，`commit()`
  照這個順序記歷程，所以歷程檔裡的原始順序是股票在前；訊息框畫的時候要自己
  重排，不是直接照歷程檔順序印）
- **整體**：新的在最上面，跟「歷程」分頁同一個慣例（`ui_history._fill_history`
  裡 `reversed(shown)` 那個做法）

### 股數／成本合併規則

歷程檔裡股數、成本是兩筆分開的事件（一格一筆）。合併成一行的判斷依據：
**同一檔股票的名稱（從 `label` 拆出來，例如「股數（2059 川湖）」取「2059 川湖」）
+ 同一個 `at` 時間戳**——同一輪寫入的話兩筆事件的 `at` 會完全一樣，這個規則
抓得到。


## 常駐顯示區（不進訊息框）

現金算法、今日初始現金餘額、「修改今日初始現金餘額」按鈕，搬到右上方變成一個
小狀態列，常駐顯示，不管這一輪有沒有異動都在。現金算法維持可點切換
（`.env` 的 `CASH_METHOD_TOGGLE` 照舊管得到要不要開放點擊）。


## 其他決定

- **訊息框要加捲軸**：現在的 `warn_box`（`tk.Text`）固定高度、沒有捲軸，裝不下
  的內容會被無聲吃掉。內容量變多之後這個風險不能再賭，一定要加捲軸。
- **視覺上色**：原本表格用列的底色／前景色做提示（負的紅字、要寫的綠底），
  改成 `tk.Text` 的 tag 上色，機制換了但視覺信號要留著（至少負的紅字這條，
  見上面「現金轉負」那節）。
